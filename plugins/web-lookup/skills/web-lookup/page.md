# ページ取得 (`page`)

URL が分かっている一般 Web ページの本文を取るときの手順。起動プレフィックスは [SKILL.md](SKILL.md) と同じ。以降は `page` だけ書く。オプションは `--help` を正本にする。

`page <url> [url ...]` は各 URL の HTML を手元で取得し、ナビ・ヘッダー・フッター・サイドバーを HTML の構造で落として本文だけを Markdown にする。API キーは要らず、URL を第三者のサービスに送らない。JavaScript は実行しない。

Microsoft Learn の URL は `ms fetch`、AWS の公式ドキュメントは `aws fetch` を使う（[SKILL.md](SKILL.md) の振り分け）。

## 判断フロー

```text
1. ログイン壁があると分かっているサイトか?（SNS・口コミサイト・地図のレビュー等）
   Yes -> 最初からブラウザ（`browser` プラグインの `using-playwright-cli` スキル）
   No  -> 2 へ

2. page <url> [url ...]

3. index.md の行を見る
   成功行（目安なし、または読んで問題のない目安） -> 本文を読む
   `failed (...)` / `too short (...)`
     -> 公開 URL なら tav extract <url> で取り直す（[tav.md](tav.md)）
        localhost・社内・非公開 URL は Tavily に渡さない -> ブラウザへ

4. 読んだ本文に次のどれかがあるか?
   - JavaScript の初期値らしき値（`0+`・`--`・空のカウンター等）
   - 必要な項目がない、ラベルだけ並んで値がない
   - ログイン・会員登録への誘導で本文が終わっている
   Yes -> 数値や項目の確認だけなら tav extract を 1 回試す。それでも欠けていればブラウザへ
          URL や取得方法を言い換えて取り直しを繰り返さない
```

**強い対象**: 1 URL = 1 コンテンツの静的ページ（ニュース記事、公式プレスリリース、技術ブログ、会社概要）。関連記事のサイドバーやマーキーのような装飾も落ちるので、`tav extract` より本文だけを読みやすい。

**弱い対象**: SPA（React / Vue 等で本文を描画するページ）、タブ切り替えの中身、ログイン後にしか出ない情報。どれも JavaScript かログインが要るので、`page` では改善しない。

## 結果の読み方

成功時 stdout は `index.md` のパスだけ。本文は出ない。

1. `index.md` を Read する。成功行は `- [title](0001.md) (N chars)`、欠落の目安があれば `—` の後ろに続く
2. 失敗した URL は成功行の後に ``- <url> — failed (HTTP 403); try `tav extract` `` の形で並び、ファイルは作られない
3. 各結果ファイルは先頭に `# {title}` と `URL:`（リダイレクト後の最終 URL）がある
4. 全 URL が失敗したときは index を作らず、各 URL の理由を stderr に出して終了コード 1

同じ URL を再実行しても上書きされず、連番フォルダが増えるだけ。

### 失敗の理由

| 表示                                             | 意味                                                            | 次の動き                                                           |
| ------------------------------------------------ | --------------------------------------------------------------- | ------------------------------------------------------------------ |
| `failed (HTTP nnn)`                              | 2xx 以外。403 はボット対策のことが多い                          | 公開 URL なら `tav extract`                                        |
| `failed (timeout)` / `failed (connection error)` | 応答なし・接続できない                                          | 公開 URL なら `tav extract`。社内 URL なら到達できる環境か確かめる |
| `failed (content-type <type>)`                   | HTML ではない（PDF・画像・JSON 等）                             | PDF はダウンロードして読む手段に切り替える                         |
| `failed (too large)`                             | 本文が大きすぎる                                                | `tav extract`（`--query` で絞る）かブラウザ                        |
| `failed (extract error: <例外名>)`               | 本文抽出で例外                                                  | `tav extract`                                                      |
| `too short (N chars)`                            | 抽出後が短すぎる。ログイン壁・JS 必須・ボット対策のページが多い | 公開 URL なら `tav extract`、それでも短ければブラウザ              |

### 欠落の目安

目安は「欠けているかもしれない」という合図で、ファイルの中身は変えない。`page` と `tav` で同じ語を使う。

| 目安               | 意味                                                         | 次の動き                                                                                  |
| ------------------ | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| `possible gaps: N` | 本文に `[...]` が N 個ある。ページ自身の省略記号のこともある | 該当箇所を読み、必要な情報が欠けていれば別経路で確かめる                                  |
| `cut off`          | 最後の行が文・表・リスト・見出しの終わり方をしていない       | 末尾を見る。メールアドレスや URL で終わるだけの誤検知もある。文の途中なら別経路で確かめる |
| `body from line N` | 最初の見出しが N 行目。手前にメニューなどが残っている        | N 行目付近から読む                                                                        |

## 既知の弱点

- **段落に入っていない数値ウィジェットが落ちる**: `3000+` のようなカウンターや実績数値が消え、ラベル（「従業員数」等）だけが残ることがある。ラベルだけの行が並んでいたら、その数値は `tav extract` かブラウザで確かめる
- **200 で一部だけ返るログイン壁**: ログイン壁のサイトは HTTP 200 で冒頭だけを返すことがあり、`too short` にならず失敗とも表示されない。文字数ではなくサイトの種類で判断する（判断フロー 1）
- **JavaScript で描画される値**: 初期値（`0+` 等）のまま、または空で出る。ブラウザへ切り替える
